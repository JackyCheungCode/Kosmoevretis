# Kosmoevretis 全站 UI 设计规范 V1.0

状态：设计系统基线；设计体系：IBM Carbon Design System v11；默认主题：Gray 10。

## 1. 设计目标
Kosmoevretis 是面向全球 3C 市场情报与客户发现的企业级数据工作平台。界面优先支持信息理解、筛选、比较、分析和决策，不采用营销型落地页或装饰性 SaaS 仪表盘的视觉语言。

## 2. 不可违反的设计原则
1. IBM Carbon Design System v11 是唯一基础设计体系。
2. 通过页面背景和 Carbon Layer 层级组织信息，以极少量边框辅助结构。
3. 数据和工作流优先；避免无意义的卡片嵌套、圆角容器和装饰阴影。
4. 相同任务类型使用相同页面模板；不同业务场景允许不同信息布局。
5. 同类控件必须使用相同 Carbon 组件、尺寸、状态和键盘交互。
6. 页面不得私自定义全站颜色、字体、控件高度、圆角和间距体系。
7. 视觉重构不得删除业务功能、改变接口参数或改变数据行为。

## 3. Design Foundation
### 3.1 主题与颜色
- 默认主题：Carbon Gray 10。
- 使用 Carbon 语义 Token：--cds-background、--cds-layer-01、--cds-layer-02、--cds-text-primary、--cds-text-secondary、--cds-border-subtle、--cds-border-strong、--cds-interactive。
- 禁止在业务 CSS 中散布十六进制颜色值。
- 状态色通过 Carbon Support Token 或 Carbon Tag / InlineNotification 表达。

### 3.2 字体
- IBM Plex Sans；缺字时使用系统无衬线回退字体。
- 优先使用 Carbon Type tokens 和 Carbon 组件默认排版。
- 禁止每个页面自行创建标题字号体系。

### 3.3 间距与网格
- 使用 Carbon spacing tokens，不建立页面私有间距刻度。
- 遵循 Carbon Grid 断点：320、672、1056、1312、1584 px。
- 页面内容宽度由 AppShell 统一控制，业务模块不得覆盖主容器宽度。
- 小屏幕按信息优先级重排，不简单缩小桌面布局。

### 3.4 边框、层级与圆角
- 以 Background、Layer 01、Layer 02 的层级差异分组。
- 边框仅用于表格分隔、表单控件边界、必要区域分界和交互焦点。
- 不增加装饰性阴影；优先采用 Carbon 组件自身形态。

## 4. Application Shell
全站 AppShell 负责顶部栏、品牌区域、全局操作、一级/二级导航、当前选中状态、移动端导航、主内容容器、页面标题、说明、面包屑和响应式规则。业务页面不得重复渲染 AppShell 已提供的页面标题或全局上下文。

## 5. 基础组件标准
| 组件 | 统一实现 |
|---|---|
| 按钮 | Carbon Button |
| 文本输入 | Carbon TextInput |
| 搜索 | Carbon Search |
| 单选下拉 | Carbon Dropdown 或项目统一 CarbonSelect |
| 可搜索下拉 | Carbon ComboBox |
| 复选/开关 | Carbon Checkbox / Toggle |
| 页内导航 | Carbon Tabs |
| 数据表格 | Carbon DataTable / Table |
| 状态 | Carbon Tag |
| 系统反馈 | Carbon InlineNotification |
| 加载 | Carbon Loading / SkeletonText |
| 空状态 | 统一 EmptyState 模式 |
| 图标 | @carbon/icons-react，禁止字符或 Emoji 代替功能图标 |

所有下拉框不得使用浏览器原生 select。自定义控件必须满足键盘操作、焦点可见、屏幕阅读器标签和一致的 Carbon 视觉行为。

## 6. 页面模板
### 分析工作台
页面标题与主要操作 → 分析对象/数据源配置 → 同级业务 Tabs → 图表和分析工作区 → 来源、时间、证据类型和置信度。

### 数据发现页
页面标题 → 搜索与筛选条件 → 执行操作 → 任务状态/历史 → 结果 Tabs → 数据表格/详情。同类发现页面共享表单、任务状态、历史和结果展示组件。

### 数据管理页
页面标题与操作 → 工具栏/筛选 → 有价值的指标摘要 → 列表/表格 → 详情或编辑工作区。

### 配置管理页
配置导航 → 页面标题与说明 → 配置表单/资源列表 → 验证与保存反馈。

### 详情与分析报告页
对象身份与核心结论 → 分区导航 → 证据、指标和分析内容 → 来源与时间元数据。

## 7. 数据可信度表达
市场情报指标应披露单位、统计周期、市场范围、数据来源、采集时间和证据类型：平台直接观测、第三方估算或 AI 推断。置信度和核验状态仅在有依据时显示，不得把估算或 AI 推断展示为已确认事实。

## 8. 交互与可访问性
- 键盘可操作，焦点状态清晰。
- 使用语义化标题、表单标签和地标区域。
- 禁止仅通过颜色表达状态。
- 加载、空、错误、成功状态使用一致反馈。
- 尊重 reduced-motion 偏好。
- 表单错误关联具体字段并说明修复方式。

## 9. CSS 与组件治理
1. 共享基础组件集中维护，业务页面优先组合共享组件。
2. 业务 CSS 只负责业务特有布局，不重新定义全站基础控件。
3. 颜色、字体、间距和状态优先使用 Carbon Token。
4. 新增例外样式必须记录原因、作用范围和移除条件。
5. 禁止全局选择器覆盖 Carbon 组件内部样式，除非经过评审。
6. 禁止堆叠 !important 修复跨页面样式冲突。

## 10. 页面验收
每页检查 Carbon 主题、字体、颜色和间距；组件复用；页面模板；重复标题与装饰性容器；加载/空/错误/成功状态；桌面/平板/手机布局；键盘导航和表单标签；业务逻辑、接口参数、权限和数据行为保持不变。

## 11. 实施顺序
1. 设计系统展示页验收。
2. AppShell 和 Design Tokens 整理。
3. 统一基础组件。
4. 页面模板落地。
5. 全球情报中心与潜在客户发现。
6. 产品中心、贸易准入、AI 分析和设置中心。
7. 全站视觉回归与防回退检查。
